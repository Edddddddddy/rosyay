# 坑点记录

## 2026-06-10：Ubuntu 24.04 应用包已安装，但 WSL 发行版注册失败

现象：

- `winget install --id Canonical.Ubuntu.2404` 成功。
- `Get-AppxPackage *Ubuntu*` 显示 Ubuntu 24.04 LTS 包状态为 `Ok`。
- `wsl --list --verbose` 没有 `Ubuntu-24.04`。
- 执行 `ubuntu2404.exe` 时失败：`WslRegisterDistribution failed with error: 0x80370114`。
- 执行 `wsl -d docker-desktop -- uname -a` 失败：`HCS_E_SERVICE_NOT_AVAILABLE`。

判断：

- 问题不在 Ubuntu 安装包本身，而在 Windows 的 WSL2/虚拟机平台后端。
- CPU 虚拟化固件已开启，但当前 Windows 会话不是管理员，无法启用或确认系统可选功能。

处理：

1. 用管理员身份打开 PowerShell。
2. 启用 `Microsoft-Windows-Subsystem-Linux` 与 `VirtualMachinePlatform`。
3. 设置 `hypervisorlaunchtype auto`。
4. 执行 `wsl --update`。
5. 重启 Windows。
6. 再启动 `ubuntu2404.exe` 完成发行版注册。

结果：

- 后续 `Ubuntu-24.04` 已成功注册并运行。
- WSL 默认用户已设为 `ubuntu`。
- WSLg GUI 环境变量正常。

## 2026-06-10：WSL 进入后默认是 root

现象：

- `wsl -d Ubuntu-24.04 -- bash -lc "id"` 显示 `uid=0(root)`。
- `/home/ubuntu` 已存在，说明系统里已有普通用户。

处理：

编辑 `/etc/wsl.conf`：

```ini
[boot]
systemd=true

[user]
default=ubuntu
```

然后执行：

```powershell
wsl --terminate Ubuntu-24.04
```

重新进入后确认：

```bash
id
echo $DISPLAY
echo $WAYLAND_DISPLAY
```

结果：

- 默认用户变为 `ubuntu`。
- `DISPLAY=:0`，`WAYLAND_DISPLAY=wayland-0`。

## 2026-06-10：PowerShell 抢先展开 WSL 命令里的 `$()`

现象：

- 在 PowerShell 中执行包含 `$(dpkg --print-architecture)` 的 WSL 命令时，PowerShell 会先尝试把 `$(...)` 当作自己的命令替换。
- 结果是 Windows 侧报 `dpkg : The term 'dpkg' is not recognized`。
- 更糟糕的是，错误输出导致 `/etc/apt/sources.list.d/ros2.list` 被写坏，后续 `apt update` 报 `Type 'Hit:1' is not known on line 1`。

处理：

- 重新写入正确的 ROS2 源文件：

```bash
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] https://mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu noble main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
```

经验：

- 复杂 Linux 命令尽量进入 WSL Ubuntu 终端后执行。
- 如果必须从 PowerShell 调 WSL，要特别小心 `$`、`$(...)`、`$!` 这些符号。
- 例如后台进程 PID `$!` 被 PowerShell 或引号层处理错时，可能出现 `kill: (2) - Operation not permitted`、`wait: ' 2': not a pid` 这类清理错误；只要节点日志和 topic 验证成功，先用 `pgrep -af ...` 确认是否有残留进程。
- 环境变量检查也尽量使用 `env | grep ...`，不要在 PowerShell 调 WSL 时直接写 `$(printenv ROS_DISTRO)`。

## 2026-06-11：克隆 ros2/examples 后不建议直接全量 build

现象：

- `~/ros2_ws/src/examples` 中有很多包，例如 `examples_rclcpp_minimal_publisher`、`examples_rclpy_minimal_publisher`。
- 这些包名和 `ros-jazzy-desktop` 已安装的 underlay 包可能重名。

- 不熟悉 overlay/underlay 覆盖关系前，先不要直接在包含 `examples` 的工作空间里无脑运行全量 `colcon build`。

## 2026-06-11：课程命令里的反斜杠需要注意格式

现象：

- 课程里有类似 `my_python_pkg \--dependencies` 的写法。
- Linux shell 中，反斜杠 `\` 用于换行续写时，必须位于行尾。

正确写法：

```bash
ros2 pkg create --build-type ament_cmake my_cpp_pkg \
  --dependencies rclcpp std_msgs \
  --node-name my_node
```

或写成一行：

```bash
ros2 pkg create --build-type ament_cmake my_cpp_pkg --dependencies rclcpp std_msgs --node-name my_node
```

不要写成：

```bash
ros2 pkg create --build-type ament_cmake my_cpp_pkg \--dependencies rclcpp std_msgs
```

## 2026-06-11：清理 build/install/log 是危险操作

说明：

- `rm -rf build/ install/ log/` 会删除整个工作空间的编译、安装和日志产物。
- 删除后需要重新 `colcon build` 并重新 `source install/setup.bash`。

建议：

- 学习阶段先记录命令，不随手执行。
- 需要清理单个包时，优先删除指定包目录，例如：

```bash
rm -rf build/my_cpp_pkg/ install/my_cpp_pkg/
```

执行前确认：

```bash
pwd
```

应显示：

```text
/home/ubuntu/ros2_ws
```

## 2026-06-11：TurtleBot3 的 `/cmd_vel` 是 `TwistStamped`


处理：


## 2026-06-10：ROS2 清华源 GPG key 缺失

现象：

```text
NO_PUBKEY F42ED6FBAB17C654
The repository 'https://mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu noble InRelease' is not signed.
```

原因：

- ROS key 没有正确 dearmor 到 `/usr/share/keyrings/ros-archive-keyring.gpg`。

处理：

```bash
sudo rm -f /usr/share/keyrings/ros-archive-keyring.gpg
curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  | sudo gpg --dearmor --yes -o /usr/share/keyrings/ros-archive-keyring.gpg
sudo apt update
```

结果：

- 清华 ROS2 noble 源索引更新成功。

## 2026-06-11：Navigation2 启动后需要先设置初始位姿

现象：

```text
AMCL cannot publish a pose or update the transform. Please set the initial pose...
Timed out waiting for transform from base_link to map
```

判断：

- 这不是导航栈安装失败。
- AMCL 需要先知道机器人在地图中的初始位置，才会发布 `map -> odom`，后续才能得到 `map -> base_link`。

处理：

- 图形界面：在 RViz 中使用 `2D Pose Estimate`。
- 命令行验证：向 `/initialpose` 发布 `geometry_msgs/msg/PoseWithCovarianceStamped`。

验证：

```bash
ros2 topic echo /amcl_pose --once
ros2 run tf2_ros tf2_echo map base_link
```

成功信号：

```text
/amcl_pose frame_id: map
map -> base_link Translation: [...]
Managed nodes are active
```

## 2026-06-11：复杂 ROS2 YAML 消息不适合跨 PowerShell/WSL 直接敲

现象：

- 用 `ros2 topic pub --once /initialpose ... '{...}'` 发布复杂嵌套 YAML 时，出现：

```text
The passed value needs to be in YAML string or a dictionary
```

原因：

- PowerShell、WSL bash、ROS2 CLI 都会处理引号和特殊字符，复杂嵌套消息很容易被某一层改坏。

处理：

- 简单消息可以继续用 `ros2 topic pub`。
- 复杂消息建议进入 Ubuntu 终端执行，或用一个小的 `rclpy` 脚本发布。

## 2026-06-11：在 PowerShell 调 WSL 时，循环变量 `$t` 也会被提前展开

现象：

- 在 PowerShell 中拼 WSL 命令时，类似 `for t in ...; do ros2 topic info $t; done` 的 `$t` 会被 PowerShell 提前处理，导致 Ubuntu 里拿不到循环变量。

处理：

- 复杂循环进 Ubuntu 终端执行。
- 或用 PowerShell 单引号 here-string 保留 `$` 字符。

## 2026-06-11：URDF 根 link 带惯性会触发 robot_state_publisher warning

现象：

```text

```

原因：

- 增加一个无惯性的 `base_footprint`。


验证：

```bash
ros2 topic echo /odom --once
ros2 run tf2_ros tf2_echo odom base_link
```

## 2026-06-11：自定义 service 的 C++ 可执行文件需要链接 typesupport

处理：

```cmake
rosidl_generate_interfaces(${PROJECT_NAME}
  "srv/SetControlMode.srv"
)

```

否则 C++ 节点 include 自定义服务头文件后，可能在构建/链接阶段出问题。
