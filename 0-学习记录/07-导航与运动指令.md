## 本次目标

从 0 实现一个 C++ Navigation2 学习项目，能启动 TurtleBot3 Gazebo 仿真、SLAM、Nav2 bringup，并提供一个 C++ `NavigateToPose` action 客户端。

## 做了什么

- 阅读教程中 Navigation2 的核心概念：`map`、`odom`、`base_link` 坐标系，BT Navigator、Planner Server、Controller Server、Behavior Server。
- 创建 C++ 功能包 `nav2_cpp_tutorial`。
- 实现 `Nav2Client` 类，封装 `/navigate_to_pose` action 客户端。
- 订阅 `/odom` 和 `/scan`，发布导航状态 `/nav2_client/status`。
- 实现 `nav2_simple_test`，用于检查 Nav2 action server 是否可用并发送示例目标。
- 编写 `nav2_params.yaml`，配置 Nav2 的 planner、controller、costmap、behavior、velocity smoother、collision monitor、docking server。
- 编写 `nav2_cpp_demo.launch.py`，一键启动 TurtleBot3 Gazebo、SLAM、Nav2 bringup，可选 RViz 和延迟测试节点。
- 建立 GitHub 标准分支流：`feature/navigation-motion-commands -> dev -> main`。

## 踩坑记录

1. Jazzy 的插件类名要用 `::`，不能沿用旧教程里的 `/`。

错误示例：

```yaml
plugin: "nav2_navfn_planner/NavfnPlanner"
plugin: "nav2_behaviors/Spin"
```

正确写法：

```yaml
plugin: "nav2_navfn_planner::NavfnPlanner"
plugin: "nav2_behaviors::Spin"
```

2. DWB controller 必须配置 critics。

否则 controller server 会因为局部规划器参数不完整启动失败。

3. `bringup_launch.py` 在 Jazzy 中会启动更多默认节点。

本次补齐了：

- `velocity_smoother`
- `collision_monitor`
- `docking_server`

其中 `collision_monitor` 缺 `observation_sources` 会报：

```text
parameter 'observation_sources' is not initialized
```

`docking_server` 缺 dock plugin 会报：

```text
Charging dock plugins not given
Failed to bring up all requested nodes
```

4. PowerShell 调 WSL 时要小心 `$` 和换行。

复杂脚本建议写成 LF 格式再交给 WSL 执行，否则可能出现：

```text
syntax error: unexpected end of file
```

5. ROS setup 脚本不适合配合 `set -u`。

`/opt/ros/jazzy/setup.bash` 会读取部分未定义变量，临时测试脚本不要开 `set -u`。
